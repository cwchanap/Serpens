# Final review fix report — strict current save decoding

## Outcome

Final whole-branch review found that schema-14 `validateSaveRecordInternal` still sent every
current save through `normalizeSandboxSavedGameInternal` before strict validation. That broad
repair path could silently reconstruct missing levels/world data, recompute stock health, clamp
industrial buffers, and relocate current-store placements.

The final fix removes that current-schema normalization. Current saves now pass directly to
`validateCurrentGameStateInternal`; malformed authoritative state produces `SaveDataError` and
uses the repository's existing empty-store fallback. The only retained pre-validation transform is
the documented in-development 28x24 retail-city regeneration path.

## RED to GREEN

The focused RED command was run before the production change:

```text
rtk bun run test:unit -- --run src/lib/persistence/saveCodec.spec.ts --maxWorkers=1 -t 'current schema save record'
```

Six regressions failed because the previous broad decoder repaired stale stock health, missing
store/building/staff level data, missing staff XP, and an over-capacity industrial buffer. After
the strict decoder change, that same focused current-schema group passed.

## Production change

- `validateSaveRecordInternal` now calls
  `regenerateLegacyRetailCitiesForStrictValidation(record.game)` and immediately strictly
  validates its result.
- Removed the broad current-save repair helpers: world/store-cap inference, store/building/staff
  level defaults, stock-health recalculation, city-feature repair, industrial-buffer clamping,
  and non-28x24 placement relocation.
- Retained only the named 28x24 retail-city regeneration. Store placement reconciliation may
  mutate only stores in a city regenerated by that exact exception; with an empty regenerated-city
  set it acts only as a strict placement validator.
- Kept the existing strict current-world freshness check. The decoder does not call
  `refreshWorldProgress` to make a current save acceptable.

## Compatibility and invariant preservation

- Task 5's authoritative city-inventory and retail-supply assignment canonical ordering remains
  unchanged.
- Task 5's independent historical-report decoding remains unchanged: malformed historical rows
  are dropped with their existing warning behavior; current authoritative game state is not
  repaired.
- A repository regression now loads an actually corrupt current-schema snapshot, observes its
  empty-summary fallback, and then proves a subsequent valid auto-save is writable/readable.
- Browser test fixtures that directly zero product stock now also write the matching derived
  `stockHealth`, so they exercise valid saves instead of relying on decoder repair.

## Scope review

The final fix changes only the persistence decoder, its persistence tests, and two E2E save
fixtures. It does not change active-city behavior, the Task 5 city-local inventory/supply
contract, report filtering, gameplay, or UI production code.

The fix is intentionally deletion-heavy: it replaces a broad normalizer with a narrow,
named 28x24 exception and preserves strict errors for all other current-schema corruption.

## Scoped re-review follow-up — unsupported retail city sizes

### Finding and focused RED proof

The retained size guard only rejected a 28x24 catalog retail city. A complete, otherwise valid
current-schema save containing a generated 20x20 Harbor City and a valid store footprint could
therefore pass the public `validateSaveRecord` path.

Before the fix, this focused public-save regression failed exactly as expected:

```text
rtk bun run test:unit -- --run src/lib/persistence/saveCodec.spec.ts --maxWorkers=1 -t 'unsupported 20x20'
```

Vitest reported one failure (349 skipped): the assertion expected `validateSaveRecord` to throw,
but it did not.

### Narrow decoder change

- `validateCurrentRetailCitySize` now accepts catalog retail cities only at the default 56x48
  dimensions.
- A direct 28x24 value retains its explicit legacy error. On the public-save path, the existing
  `regenerateLegacyRetailCitiesForStrictValidation` pre-validation exception runs first, so the
  documented 28x24 regression continues to pass after regeneration.
- Every other non-default catalog retail size, including 20x20, now throws `SaveDataError` before
  later placement checks. Industry cities and non-catalog cities remain outside this helper.

The targeted regression became green after that change: one test passed (349 skipped).

### Test-fixture alignment

The new current-save contract made several intentionally tiny persistence fixtures invalid before
they reached their intended assertions. Those test-only fixtures now generate a deterministic
default-size Harbor City with a valid store tile. The shared scenario fixture now derives its
valid game from `createNewGame` while retaining the official scenario seed and cash setup. No
production normalizer, inventory behavior, or Task 5 logic changed in this follow-up.
